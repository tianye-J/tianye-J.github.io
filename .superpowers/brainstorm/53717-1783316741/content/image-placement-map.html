两篇 RoboCup 入门文的配图点位地图

目标不是给每段都加图，而是在读者最容易丢失系统感的位置放视觉锚点。

必配：承担全局理解 推荐：解释抽象机制 可选：增强记忆点

RCSSServerMJ 入门指南

关键词：球场 + 裁判 + 物理世界；从 Server 视角看整场比赛。

0

文章封面 / 列表图

一张“MuJoCo 球场 + Server 控制台 + 多个 Client 连接”的系列封面，只在列表页露出。

1

第二章：Client-Server 架构

把现有 ASCII 数据流换成更清楚的 Server 居中、多 Client 下挂的架构图。

2

第四章：长度前缀 + S-expression

画成 byte strip：4 字节长度前缀 + N 字节消息体，再接 S-expression 树形结构。

3

第五/八章：每 20ms 主循环

做一张 Server / Client 双泳道循环图，连接物理步进、感知生成、动作接收、PD 控制。

4

第六章：PD 控制器

弹簧 + 阻尼器的小图，帮助非控制背景读者记住 kp/kd 的直觉。

Janus 客户端入门指南

关键词：球员大脑；从感知解析到决策，再落到 23 个电机动作。

0

文章封面 / 列表图

一张“球员大脑”风格封面：感知输入、World 状态、Decision、Skills、Motor 输出。

1

第二章：Agent 主循环

把 receive → world.update → decision → send 四步做成核心总览图，作为全文地图。

2

第四章：WorldParser 感知解析

S-expression 进入 parser，分流到 World / Robot；旁边补一个右队坐标翻转示意。

3

第六章：T1 机器人 23 个电机

用正面人体骨架图标注 he/lae/rae/lle/rle，降低命名表的阅读负担。

4

第七/九章：决策到 Walk

一张从 carry_ball 目标点到 Walk observation、ONNX、23 关节目标的动作链路图。

5

第十一章：GetUp 状态机

摔倒检测 → 稳定 → 判断前/后摔 → keyframe → 原地踏步恢复平衡。

先选一个配图密度方向

A

少而精

每篇 1 张列表封面 + 3 张正文核心图。阅读节奏最轻，我推荐先走这个版本。

B

教材式

每篇 1 张列表封面 + 5 到 6 张正文图。解释更充分，但长文会显得更像教程讲义。

C

系列化

先做一张 Server ↔ Janus 总图，再给每篇各配 3 张。两篇文章之间的联动感最强。
